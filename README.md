# Gauteng Property Market Analysis

An end-to-end analytics project: raw, messy property-sales data → cleaned and validated → analysed in SQL → ready for a dashboard. It answers the questions an estate agency or property investor would ask about the Gauteng residential market.

> **Data disclosure:** the dataset is **synthetic** (generated by `src/generate_data.py`). Suburb price levels are illustrative assumptions, not real market figures, so the *numbers* are not market insights. The project demonstrates the *method*. See [Using real data](#using-real-data) to swap in a real dataset.

## Business questions

1. How do suburbs compare on volume, sold price and price per m²?
2. Is the market rising? What are the monthly and year-on-year trends?
3. Which suburbs sell below the market price per m² for the same property type?
4. How quickly do properties sell, and how much do buyers negotiate off the asking price?
5. Which suburbs lead on sales volume each year?

## Pipeline

```
generate_data.py  →  clean_data.py  →  DuckDB  →  sql/*.sql  →  outputs/*.csv  →  dashboard
 (raw, messy CSV)   (validated, logged)  (listings)  (5 analyses)   (BI-ready)      (Power BI / Tableau)
```

## Run it

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python src/generate_data.py    # creates data/raw/listings_raw.csv
python src/clean_data.py       # cleans, logs data quality, loads DuckDB
python src/run_queries.py      # runs all SQL, writes CSVs to outputs/
```

## Data dictionary (cleaned `listings` table)

| Column | Description |
|---|---|
| `listing_id` | Unique listing identifier |
| `suburb` | Standardised suburb name (12 suburbs) |
| `property_type` | House, Apartment or Townhouse |
| `bedrooms` | Number of bedrooms (nullable) |
| `floor_size_m2` | Floor size in m² (nullable when missing or implausible) |
| `list_date`, `sold_date` | Date listed / date sold (sold date null if withdrawn) |
| `list_price_zar`, `sold_price_zar` | Prices in rand as numbers |
| `status` | `Sold` or `Withdrawn` |

## Data quality: what was wrong and what I did

The raw file is deliberately messy. `clean_data.py` logs every step to `outputs/data_quality_report.csv`.

| Problem | Treatment | Why |
|---|---|---|
| Duplicate listings | Removed by `listing_id` | Duplicates inflate sales counts |
| Suburb spelling (case, spacing, abbreviations) | Standardised via lookup | Otherwise one suburb splits into several groups |
| Prices stored as text (`R 2 450 000`) | Parsed to numbers | Text can't be aggregated |
| Impossible floor sizes | Set to null, row kept | Keeps the sale but excludes it from price per m² |
| Missing bedrooms / floor size | Left null, not imputed | Guessing would bias the results |
| Sold date before list date | Removed | Impossible; logged |

## SQL skills demonstrated

| File | Skills |
|---|---|
| `01_suburb_overview.sql` | Aggregation, `MEDIAN`, `FILTER`, NULL handling |
| `02_price_trend.sql` | CTEs, window functions (`AVG OVER`, `LAG`), date truncation |
| `03_below_market_suburbs.sql` | Multiple CTEs, joins, `RANK() OVER (PARTITION BY …)`, `HAVING` |
| `04_speed_and_negotiation.sql` | `DATE_DIFF`, `CASE` price bands, ratio metrics |
| `05_top_suburbs_per_year.sql` | `ROW_NUMBER`, share-of-total with window `SUM` |

## Key findings

> *Write these yourself after running the pipeline and building the dashboard. Three to five plain-English sentences, each with a number, e.g. "Suburb X sells at Y% below the market price per m² for apartments but takes Z days longer to sell." Keep them clearly labelled as findings from the synthetic dataset unless you have swapped in real data.*

## Limitations

- Synthetic data: relationships in it were designed, not observed.
- "Below market" is a screening signal only. It ignores condition, stand size, security estates and other drivers of price.
- Median price per m² for houses uses floor size only, not stand size.

## Using real data

Replace `data/raw/listings_raw.csv` with a real export using the same column names, then extend the suburb lookup in `src/clean_data.py`. Suitable sources include your own sales records (anonymised), Stats SA data, or public housing datasets.
